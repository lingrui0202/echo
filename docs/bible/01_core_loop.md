# 01 · 核心循环

> 状态：✅ 已实现（第 7 周补上了风险循环）

## 三层循环

| 层 | 时长 | 循环 |
|---|---|---|
| 秒级 | 1–3 s | 走 → 看/听 → 决定方向 → （必要时）发声呐 |
| 一局 | 60–180 s | 出生 → 探路 → 找到出口 → 结算 → R |
| 元层 | 10 局 | 改一个参数 → 跑一组 → 看 Tab / `runs.json` → 修正预测 |

## 秒级循环（现在）

```
移动（235 px/s）
   ↓
看见：脚下 56 px 光圈 + 之前留下的墙痕
   ↓
不确定 → 空格发声呐（冷却 1.8 s）
   ↓
波前从 0 推到 672 px，撞墙反射，墙被「点亮」1.6 s
   ↓
玩家据此修正脑内地图 → 继续走
```

关键：**看见是瞬时的，记住是持续的**。波前 1.6 s 后消失，墙痕 6–7 s 后退掉，剩下全靠记忆。

## 一局流程

1. 出生在 (1,1)，全黑，只有脚下一圈。
2. 探索；每次发声呐计入 `sonar_count`。
3. 进入出口 `Area2D` → `Player.win()` → `GameLog.end_session("win")`；
   中途被敌人碰到 → `Player.caught()` → `end_session("caught")`。
4. 屏幕中央弹结算：用时 / 声呐次数 / 走过格数 / 重复率（通关是蓝标题，被抓是红标题）。
5. `R` 重开，`Tab` 看最近 10 局均值。

## 反馈链（报告里直接用）

| 层 | 内容 |
|---|---|
| 规则 | 声呐有冷却；波会被墙挡住/反射 |
| 系统 | 射线推进 + 光照遮挡 + 冷却计时 + 撞墙记忆 |
| 反馈 | 波前扩散、墙痕、状态行计时/次数、结算面板 |
| 玩家行为 | 敢往深处走、开始记路、控制发声频率 |

## 节奏问题（第 7 周的判断）

- 波 1.6 s、冷却 1.8 s → **占空比 89%**，理论上可以边走边扫，和「靠记忆」的目标矛盾。
- 波半径 672 px ≈ 10.5 格，一屏 18 格宽，扫一次能看清大半屏。
- 下一轮的改法（择一，需实测）：

| 方案 | 做法 | 占空比 | 代价 |
|---|---|---|---|
| A | 冷却 1.8 → 2.4 s | 67% | 操作变钝 |
| B | 波没消失不能再发 | 最多 100%，强制等 1.6 s | 手感更「重」 |
| C | 有限次数（8 次 + 每 20 s 回 1） | 取决于路线 | 要改 HUD |

> 当前默认值是 A 之前的 1.8 s；下一轮用 `runs.json` 的 `config` 做对照再定。

## 风险循环（✅ 第 7 周）

```
发声呐 → 700 px 内的敌人听见（穿墙）→ 朝声源走 4 s，110 px/s
      → HUD 闪 1.5 s「！有东西听见了」
      → 接触到玩家（20 px）→ caught → 结算 → R
```

理想节奏：听见提示 → 停一下、听/看 → 决定继续还是绕路 → 敌人 4 秒后停在原地。
敌人比玩家慢（110 vs 235），所以永远跑得掉；代价是**位置暴露了 4 秒**。

设计意图：让「发声」从纯收益变成**有代价的选择**，玩家开始权衡「这一声值不值」。

## 时长预算

- 最短 144 步 × (64 / 235 s) ≈ 39 s 纯移动。
- 加找路、犹豫、绕路，目标一局 90–180 s。
- 超过 3 分钟没有进展 = 关卡太大或提示不足，要改地图而不是加光。

3. 它能不能被 `runs.json` 量化？
4. 它会不会让「记忆」这件事变得不必要？
