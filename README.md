# 回声定位探索（垂直切片）

> **Echo（回声）** · 计算机图形学与游戏开发 · 两人小组项目
> 设计圣经：[docs/bible/_index.md](docs/bible/_index.md)（数值 / 规则 / 实体 / 决策，写代码前先看）
> 设计说明：[docs/Echo_项目准备说明_第4周作业.pdf](docs/Echo_项目准备说明_第4周作业.pdf)
> 引擎：Godot 4.7.2 · 入口场景：res://scenes/Level01.tscn


全黑洞穴里，你只能靠一次次的**声呐脉冲**看清周围——光波扩散出去，被墙挡住的地方依然漆黑。
这个工程已经把核心机制、关卡生成、通关判定和**遥测**都跑通了，是一个可以往上长骨架。

---

## 怎么运行

- 图形界面：用 Godot **4.7** 打开 `project.godot`，按 **F5**。
- 命令行：
  ```
  Godot_v4.7.2-stable_win64.exe --path <本目录>
  ```

## 操作

| 键 | 作用 |
|---|---|
| `WASD` / 方向键 | 移动 |
| `空格` | 发声呐（冷却 1.2 秒） |
| `Tab` | 打开/关闭数据面板 |
| `R` | 重开本关 |

## 现在有什么（脚本与自检验证过）

- **全黑画面** + 玩家脚下一圈常亮光（半径 56 px、能量 0.75、环状）——只够看清边界，看不见下一个格子。
  第 5 周试玩反馈「还是能看清路、和普通迷宫没区别」，所以从 128 px / 0.9 收到 56 px 的环。
- **声呐波前**：一次推出一圈几何波前（最多 5 次反射），被墙挡住；撞到的墙会留 5–6 s 的淡蓝痕迹。
- **会听见你的敌人**（第 7 周）：发声后 700 px 内的敌人朝声源走 4 s，碰到即结算「被听见了」。
- **地图由 ASCII 生成**：碰撞体、光照遮挡体、视觉、敌人生成点全部由同一张 `MAP` 推出。
- **出口与通关**：走到绿色菱形即通关；结算面板列用时 / 声呐次数 / 走过格数 / 重复率。
- **遥测**：每局结束记一条 JSON：用时、声呐、格子、重复率、被听见次数、参数快照。
- **数据面板**：`Tab` 查看最近 10 局均值与最好成绩。

## 你该动的三个参数（这就是实验变量）

一次**只改一个**，先写下预测，再运行，然后按 `Tab` 看数据。

1. `scripts/player.gd` → `SONAR_COOLDOWN = 1.2`
   声呐冷却。调大 → 更紧张、更依赖记忆；调小 → 更从容、更像"手电筒"。
2. `scripts/sonar.gd` → `DURATION` / `MAX_SCALE` / `PEAK_ENERGY`
   脉冲的持续时间与能照多远。
3. `scenes/Level01.tscn` → `CanvasModulate.color`
   整体黑暗程度。太暗会让人烦躁，太亮就没有探索感——这个阈值值得实测。

想改关卡：编辑 `scripts/level.gd` 里的 `MAP` 数组，`#` 是墙、`.` 是地面、`E` 是出口，
边界墙由代码自动补齐。起点在 `START` 里改。

- **目标体验一句话**：我希望玩家在 5 分钟内感到"紧张但逐渐掌控"——靠有限次数的声呐把黑暗变成一张记住的地图。

- 记住这门课真正在看的是：**能不能运行、能不能解释、能不能发现偏差并修正**。所以每处改动都记下"改了哪个文件哪个参数、预测什么、实际观察到什么"。

## 第 6 周改动：大地图、2 格通道、结算面板、会反射的声呐（2026-11-03）

上周试玩结论是「15.8 秒就通关，太简单，地图太小」。这周按那个结论改，最后落地成这样：

| 改了什么 | 第 5 周 | 现在 |
|---|---|---|
| 地图 | 30×16，最短 42 步 | **61×34，通道 2 格宽，最短 144 步** |
| 声呐冷却 | 1.2 s | **1.8 s** |
| 一局结束 | 状态行末尾加一句话 | **屏幕中央弹结算面板**：用时 / 声呐次数 / 走过格数 / 重复率 |
| 重复率 | 每帧采样（站着不动也能到 0.95） | **按进入格子的次数算**，才是“有没有走回头路” |
| 声呐 | 一圈向外扩的光 | **一次推一圈、最多五次反射的波前** |

### 地图

- 生成器 `tools/make_maze2.py`（纯 Python，不依赖 Godot）：DFS 迷宫 + 环路 + 5 个 5×5 房间；逻辑格 2×2 字符 + 1 格墙 → 61×34，通道 128px。改种子后生成的 `maze2_rows.txt` 直接贴进 `scripts/level.gd` 的 MAP。
- 起点 (1,1)，出口 (26,14)，用 BFS 核对最短 144 步。
- 为什么改成 2 格：1 格走廊里波反射会碎成一片小光斑，屏幕看着乱。

### 声呐

- 一次发声推一圈：420 px/s、1.6 s、最多 **5 次**反射，每反射一次亮度 ×0.72。
- 每条射线带“剩余路程”推进，撞墙按法线反射、扣掉已走路程，220 条射线的末端连成波前 —— 所以在墙角会拐弯。
- 没有任何振荡量参与显示：只画“当前半径”这一圈，亮度随半径变淡，不会一帧亮一帧暗。
- **撞墙留痕**：射线打到的墙面会以淡蓝色记在一张小图上（只记前两跳），6–7 秒内慢慢退掉 ——
  相当于“记住摸过的墙”。圈结束后衰减仍继续（`_process` 里先衰减，再判断圈还在不在）。
- 波画在 `follow_viewport_enabled` 的 CanvasLayer 上：`CanvasModulate` 会把同一 canvas 乘到 0.015，
  直接画在关卡里等于没画。
- `scripts/sonar.gd` 的圆形光环和圆弧已关闭（`RING_PEAK = 0`），只留 0.12 的余辉。
- 可调：`RING_SPEED`、`DURATION`、`MAX_BOUNCES`、`BOUNCE_LOSS`、`SEGMENTS`。

> 中途试过“在网格上跑二维波动方程”，因为每帧正负翻转、还在墙之间来回弹，屏幕光暗一直在变，已弃用。

### 结算与数据

- 通关时屏幕中央弹面板：用时 / 声呐次数 / 走过格数 / 重复率，按 R 再来一局。
- 重复率改成 `1 − 去重格数 / 进入格子次数`，站着不动不再刷到 0.95。

### 验证

- `tools/smoke.gd`：挪到第 2 行走廊，1.0 s 右移 235 px；顶墙停在 x=3447（墙面 3456）；冷却 1→1→2（1.8 s）
- `tools/test_win.gd`：瞬移到 (26,14) → 结算面板 visible = true，截图 `_verify/win_panel.png`
- `tools/wave_shots.gd`：长走廊发一次声呐，200–1600 ms 连拍，见 `_verify/wave_strip.png`

### 遥测：每条记录带上这局的参数

以前 `runs.json` 只记结果，改完冷却再跑，两份数据分不清是哪套参数。现在每条记录多一个 `config`：

```json
"config": {
  "sonar_cooldown": 1.8, "ambient_radius": 56, "ambient_energy": 0.75,
  "level": "Level01.tscn", "map_w": 61, "map_h": 34, "cell": 64,
  "wave_speed": 420.0, "wave_duration": 1.6, "max_bounces": 5, "segments": 220
}
```

- `player.gd` 记冷却与光圈，`level.gd` 记地图与波参数。
- `runs.json` 最多保留 200 条（`MAX_RUNS`），面板里加了「最好成绩」和「本局参数」。
- `tools/smoke.gd` 的冷却从 `player.gd` 的常量读，`tools/test_win.gd` 的出口格从关卡读，不再各写一份。

### 新增自检场景（不依赖 `--script`）

```
Godot_v4.7.2-stable_win64_console.exe --path <本目录> res://tools/selfcheck.tscn
```

跑完自动退出，写 `_verify/selfcheck.txt`，并截 `selfcheck_wave.png`（波前）和 `selfcheck_win.png`（结算面板）。
检查项：墙数、出口格、全黑层、相机限位、`GameLog.config`、波前采样点数、HUD 文案不重复、结算面板弹出。

实测（RTX 3050 / Vulkan Forward+ / 1152×648，三次运行）：

| 项 | 实测 |
|---|---|
| 波前 `_compute_ring`（221 条射线，最多 5 次反射） | **1175 / 1246 / 1191 µs 每帧** |
| 边界记忆 `_decay_edges`（122×68 像素，每 4 帧一次） | **455 / 491 / 439 µs 每次** → 平均约 0.12 ms/帧 |

结论：这两处暂时不是瓶颈（1.2 ms ≈ 60 fps 预算的 7%），所以**这周没有**动「复用 ray query / 降到 144 段 / 只衰减活跃格」。等敌人进来、单帧预算变紧时再复查，避免为了 0.5 ms 改坏已经调好的手感。

### 首页 · 多槽存档 · 评级

启动后先进首页（`scenes/MainMenu.tscn`），不再直接进游戏：

| 入口 | 做什么 |
|---|---|
| 新存档 | 开一个新槽，从第 1 关开始，**只有这里会弹新手引导** |
| 加载存档 | 按最近保存时间列出所有槽（创建时间 / 第几关 / 已通 X/5 关），按 1–9 载入 |
| 测试 | 5 关全开、不发词条、不写存档与遥测，和正式存档完全隔开 |
| 排行榜 | 每关分开，读 `runs.json` 的历史成绩；开新存档不清它 |
| 设置 | 亮度 / 音量 / 声呐配色 |

- 存档文件：`user://saves/<id>.json`，一槽一个（id 带毫秒，避免同秒撞车）；
  通关、换关、回首页都会落盘；旧的 `progress.json` 会自动迁移成第一个槽。
- 列表显示**创建时间**（本地时区）；保存只刷新「最后保存时间」，不影响显示，免得看起来像多了一个档。
- 游戏里 `Esc` 面板：`1/2/3` 亮度音量配色、`4/5` 换关、`6` 重置进度、`7` 回主菜单。

**评级**：目标时间 = 该关最短路时间 × 2（第 1 关约 62 s、第 5 关约 97 s），
被听见每次按慢 5% 计入。实际 ÷ 目标 ≤1.0 是 S、≤1.35 是 A、≤1.75 是 B、≤2.3 是 C，其余 D。
结算面板会写出「用时 X s（目标 Y s）」，规则可以自己核。

### 追击：追实时位置，不再是旧坐标

之前 `_target` 只在 `hear()` 里写一次，玩家一走它就朝旧点跑；速度 110 还不到玩家的一半，基本抓不到人。现在：

| 项 | 之前 | 现在 |
|---|---|---|
| 目标 | 发声那一刻的格子（固定） | **每 0.25 s 刷新到玩家当前格** |
| 速度 | 110 px/s | **168 px/s**（玩家 235，直线仍跑得掉） |
| 追击时长 | 4 s | **5.5 s** |
| 放弃条件 | 计时到 | 计时到 **或** 距离 >900 px 持续 1.5 s |
| 接触判定 | 20 px | 24 px |

自检 `tools/chase_check.tscn`：站桩玩家 1.3 s 被抓；全速跑 5 s 抓不到 —— 两头都卡住了。

### 会听见你的敌人（同一周做的）

上一轮的结论是「声呐只有收益、没有代价」。所以把代价补上：**你一发声，附近的东西就朝你来。**

### 规则

- 玩家发声呐 → 关卡把声源广播给所有敌人（`level._alarm`）。
- 敌人在 **700 px** 内听见（**穿墙**，不做视线）→ 朝声源走 **4 秒**，110 px/s。
- 距离 ≤ **20 px** → 结算面板「被 听 见 了」，`reason = "caught"`。
- 每一声惊动至少一只敌人时，HUD 左上闪 1.5 s「！有东西听见了」；遥测新增 `alerts`。

### 出生点：不写死坐标，也不再「藏在深处」

先算「起点 → 出口」的最短路（144 步），取路线 **30%** 和 **65%** 两处作锚点，
在锚点的四邻里找一个**不在路线上**的开放格；两只间隔 ≥10 格，排除起点/出口。

本周地图落在 **(20,23) / 45 步** 与 **(41,7) / 96 步**，路径离敌人最近 **1 格**。
第一只大约在正常路线的 1/3 处，玩一分钟内就会经过；偏一格是为了不把唯一通道堵死。

### 寻路

新增 `scripts/maze.gd`：`path()` 用来算「起点→出口」路线（选出生点）和敌人追击路径；
`distances()` 留作距离统计/校验。没有用 `NavigationRegion2D` —— `MAP` 已经是权威数据。

### 反馈

- 敌人自带 192 px 红色微光（`shadow_enabled`，约 3 秒一次呼吸，追击时亮 1.6 倍），3 格内能提前看到，不至于「无故死亡」。
- 结算面板复用：通关是蓝标题，被抓是红标题「被 听 见 了」，数据项一样。

### 验证（`tools/selfcheck.tscn`，全部 PASS）

- 敌人 2 只、出生点在空地、距起点 45 / 96 步、可达、不在出口上、**不在最短路上**（离路线最近 1 格）；
- 听觉半径外不追、半径内追；`emit_wave` 广播能惊动敌人、`alerts` +1；
- 敌人听到后**真的移动**（第 12 帧测到 18.3 px，不是只翻了个标志位）；
- 被抓后 `reason = caught`，结算面板显示「被 听 见 了」；
- 波前 **1166–1333 µs/帧**、边界记忆 **429–450 µs/次**（多次运行），与上周持平；自检窗口 60 帧 ≈ 0.8 s（约 75 fps，含 2 个敌人和 2 盏阴影灯，粗略值）。
